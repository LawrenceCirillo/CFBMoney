# CFB Money invariants

- The Build salary cap is $55M. Valid published rosters spend the exact selected book in integer $0.1M increments. The 22-player and special teams market ceilings have $78.3M total headroom, so the full $55M is spendable. These slots are modeled investments, not literal individual salary estimates: $55M divided by 23 slots averages $2.39M. Do not change this math casually.
- The regular-season opponent and home/away slate is fixed for each `(program, seed)` and is independent of roster quality, gravity, gameplan, and results. Do not introduce injuries or a gameplay depth system.
- Program Gravity uses only `data/program-gravity.json`, version `v1`. A tagged group computes talent from `effectiveSpend = actualSpend * (1 + gravity)`. Actual spend still costs exactly the same dollars, and diminishing returns apply to effective spend. Do not put gravity into the opponent schedule.
- Gravity is on by default in Build setup. Off is Pure parity. Persist `gravityOn` and `gravityVersion` in each published season and apply the same table in server replay. Bump `SIM_VERSION` for any game-model change so older seasons remain in the unranked archive with live share pages.
- `cappedOptimalAllocation()` accounts for gravity in marginal-gain water filling. Preseason expected wins includes the roster's gravity but assumes neutral weekly gameplans. The ranked leaderboard opens on overachievement.
- Gravity acceptance uses the final user criterion: preserve the researched tag magnitudes and scoring model; verify per-program directionality (leaning beats ignoring), controlled monotonicity (a larger tag yields a larger gain on the same roster and schedule), and report measured expected-win gains without a minimum. `npx tsx scripts/tune-playoff.ts` writes `docs/gravity-tuning.md`.
